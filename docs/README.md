# 文档索引

接手项目或上下文丢失时，按下面顺序读；每类信息只在一个地方维护。

1. [00-当前状态与任务.md](00-当前状态与任务.md)：**唯一任务看板**。当前阶段、下一步、任务状态、设备基线和禁止事项只看这里。
2. [02-开发进度日志.md](02-开发进度日志.md)：**唯一开发日志**。实现过程、代码复核、真机数据、历史结论和测试记录都写这里，其他文档不维护动态信息。
3. [01-架构与关键决策.md](01-架构与关键决策.md)、[05-播放器替换设计.md](05-播放器替换设计.md)、[06-VPU鲁棒性架构.md](06-VPU鲁棒性架构.md)：**设计与已拍板决策**。只写边界、接口、结构和机制，不写日期化开发日志。
4. [08-统一调试与日志系统设计.md](08-统一调试与日志系统设计.md)：统一 debug 入口、单一日志、按内容类型的 session 标识、命令化场景复测与 dmesg 关联的设计。
5. [04-构建与真机调试.md](04-构建与真机调试.md)：工具链、构建、部署、截图和排查命令；待统一调试系统落地后整体翻新。
6. [03-踩坑与经验.md](03-踩坑与经验.md)：API、同步、curl、borealis、设备等长期有效的踩坑结论。
7. [07-开发纪律.md](07-开发纪律.md)：复核真实代码、分层回归、先测试后提交、任务单一入口等通用纪律。

## 维护规则

- 任务只在 `00`；开发日志和动态只在 `02`；`01/05/06` 只维护设计与决策。
- 每个阶段结束：更新 `00` 的任务状态，在 `02` 追加一条含证据的记录。
- 视觉/听觉结论必须注明“用户确认”或“截图确认”，不能只凭日志推断。
- 不往 [archive](archive/规划-完整历史-2026-11-16.md) 续写；归档只读备查。
- git 提交按 [07](07-开发纪律.md)：先测试后提交、按主题拆分、明确 `git add`、不提交 `.workbuddy/`。
