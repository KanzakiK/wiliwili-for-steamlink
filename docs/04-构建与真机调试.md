# 构建与真机调试

## 一、环境

- 主机：Windows + WSL2（Ubuntu 26.04）
- SDK：`~/steamlink-sdk`（含 `setenv.sh`、`rootfs`、`toolchain`）
- 交叉编译器：`armv7a-cros-linux-gnueabi-gcc/g++`（GCC 9.2.0）
- 设备：`<device-ip>`，root / `<device-password>`

### 必须注意

- C++ 编译器依赖 `libmpfr.so.4`，必须设置：
  `export LD_LIBRARY_PATH=$HOME/steamlink-sdk/toolchain/lib:$LD_LIBRARY_PATH`
- CMake 用工具链文件：
  `-DCMAKE_TOOLCHAIN_FILE=$HOME/steamlink-sdk/toolchain/steamlink-toolchain.cmake`
- CMake 4.x 需要：`-DCMAKE_POLICY_VERSION_MINIMUM=3.5`
- 环境变量：`MARVELL_SDK_PATH`、`MARVELL_ROOTFS`
- CMake 识别交叉编译器：显式 `export CC=armv7a-cros-linux-gnueabi-gcc CXX=...`（仅设 `_COMPILER_INIT` 不够）

## 二、构建产物

### 1. 自编静态 libcurl（cpr 要求 ≥7.68，SDK 只有 7.26）

```sh
sh app/scripts/build-curl.sh
# 安装到 ~/steamlink-curl（curl 7.79.1，OpenSSL 1.0.1c + zlib）
```

### 2. wiliwili 整仓（当前使用）

```sh
sh tools/build-wiliwili.sh
# MPV 头文件 → ~/mpv-stub，构建目录 ~/build-wiliwili，产物 ~/build-wiliwili/wiliwili
# 资源在 ~/build-wiliwili/resources
```

脚本会设置 PATH/LD_LIBRARY_PATH/CC/CXX/MARVELL_*，然后 CMake 配置 + make。

### 2c. libmpv 兼容层 + 播放子进程（进程隔离架构）

**两个独立二进制，分属两个进程：**

```sh
# 1) libmpv 兼容层（IPC 客户端，链进 wiliwili）
#    源码 tools/mpv-stub/mpv_stub.c，编译成 ~/mpv-stub/lib/libmpv.a
sh tools/build-wiliwili.sh    # 脚本第 2 步自动编译（gcc + -D_DEFAULT_SOURCE -pthread）
# 协议头 player/include/IpcProtocol.h 由脚本自动复制到 ~/mpv-stub/include/

# 2) 播放子进程（SlPlayer + IPC server）
export MARVELL_SDK_PATH=$HOME/steamlink-sdk MARVELL_ROOTFS=$HOME/steamlink-sdk/rootfs
export PATH=$HOME/steamlink-sdk/toolchain/bin:$PATH
export LD_LIBRARY_PATH=$HOME/steamlink-sdk/toolchain/lib:$LD_LIBRARY_PATH
cmake -S player -B ~/build-slplayer && cmake --build ~/build-slplayer -- -j4
# 产物：~/build-slplayer/{slplayer_test, slplayer_daemon, ipc_probe, compat_test}
```

| 产物 | 作用 |
|---|---|
| `wiliwili` | UI 主进程，链接 `libmpv.a`（兼容层） |
| `slplayer_daemon` | 播放子进程，SlPlayer + Unix socket IPC server |
| `ipc_probe` | IPC 链路调试探针（不开 UI 直接验证 daemon 控制/事件面） |
| `compat_test` | 兼容层独立验证（链 `libmpv.a`，模拟 wiliwili 调用序列） |

watchdog 阈值默认值：`SL_WATCHDOG_POLL_MS=500`、`SL_WATCHDOG_NOHB_MS=3000`、`SL_WATCHDOG_STALL_MS=1500`、`SL_WATCHDOG_GRACE_MS=2000`；设 `SL_WATCHDOG_DISABLE=1` 可临时关闭 watchdog（仅用于对照实验）。

真实 BV 回归：`tools/build-wiliwili.sh` 会自动应用 `tools/patches/wiliwili-open-bv-test.patch`，给 wiliwili 增加 `--open-bv <BV号>` 测试入口；启动命令可加 `SL_TEST_PAUSE_AFTER_SEC=8` 在真实播放 8 秒后自动 pause/resume。`SL_SYNC_DEBUG=1` 会输出音视频对齐阶段日志。该 patch 只调用 wiliwili 的 `Intent::openBV()` / `MPVCore::pause()` / `resume()`，不替换播放链路。

**IPC 约定**（详见 `player/include/IpcProtocol.h`）：

- socket 路径默认 `/tmp/slplayer-ipc.sock`，可用环境变量 `SL_IPC_SOCKET` 覆盖
- 帧格式：4 字节小端长度 + 文本 payload（TAB 分隔字段）
- 控制面 `open/pause/resume/seek/stop/quit/volume/heartbeat`；事件面 `opened/playback_start/progress/paused/resumed/seeked/eof/error/fatal/heartbeat`
- 数据面（视频/音频）不经过 IPC，仍由 SLVideo/SLAudio 走硬件层

**启动时的环境变量**：

- `SL_DAEMON_PATH`：daemon 二进制路径（默认 `/tmp/slplayer/slplayer_daemon`）
- `SL_TRANSPARENT`：透明层开关，**由兼容层运行时 setenv/unsetenv 控制，启动脚本绝不要设**（设了会让整个 UI 全程透明，首页露出空视频平面变黑底）
- `/tmp/slplayer_vpu.lock`：VPU Dirty Flag，由 SlPlayer 自管；强杀会残留、正常退出会清除

## 三、部署到真机

> **⚠️ `/tmp` 是 tmpfs（内存盘），禁止把二进制/资源/测试视频长期放在里面。** 设备只有约 269MB 内存、无 swap；tmpfs 占用会直接减少可用内存。正式部署一律走 `/home/apps/bilibili`（ext4 真实存储）。诊断方法与历史现场见 [03 踩坑](03-踩坑与经验.md) 和 [02 日志](02-开发进度日志.md)。

### 正式部署：一条命令

```sh
sh tools/steamlink-app/install.sh     # 在 WSL 里跑
```

脚本 6 步：校验本地产物 → 建目录 → 部署 toc/脚本/图标 → 部署二进制 → `tar` 部署 resources → **检查设备内存与 `/tmp` 占用**（超过 10MB 直接告警）。

### 临时验证单个新构建（不进主菜单入口）

即使只是临时验证，也**不要把文件放 `/tmp`**。放安装目录下的临时名，再用 `mv` 原子替换（避免覆盖正在执行的二进制）：

```sh
APP=/home/apps/bilibili
scp ~/build-wiliwili/wiliwili root@<device-ip>:$APP/bin/wiliwili.new
sshpass -p <device-password> ssh root@<device-ip> \
  "chmod 755 $APP/bin/wiliwili.new && mv $APP/bin/wiliwili.new $APP/bin/wiliwili"
```

- 手动前台启动：`ssh root@<设备> "$APP/bilibili.sh"`（会设好 HOME/SL_DAEMON_PATH）
- 程序退出后 Steam Link UI 会自动重启（`shell.sh` 的 while 循环）
- 日志：`ssh ... tail -f /tmp/wiliwili.log`（首行 `[boot]` 记的是启动时 `MemFree`/`Shmem`/`/tmp` 占用，**排查 OOM 先看这行**）
- 想边播边看内存曲线：`ssh ... "sh /tmp/memwatch.sh &"`，日志 `/tmp/memwatch.log`（脚本源在 `tools/steamlink-app/memwatch.sh`）

### 部署内容（wiliwili + 播放子进程）

统一走 `install.sh`：

```sh
sh tools/steamlink-app/install.sh
```

它把 `wiliwili`、`slplayer_daemon`、`resources/`、`toc.txt`、`bilibili.png`、`bilibili.sh` 全部装到 `/home/apps/bilibili/`，并在最后打印设备内存与 `/tmp` 占用。

**部署注意事项**：

- 资源用 `tar czf` + `scp` + 设备端解包，不用 `scp -r resources/*`（设备 scp 对目录展开有问题）。
- 覆盖运行中的二进制先传 `xxx.new` 再 `mv`，避免 `Text file busy`。
- daemon 先启动并等待连接；兼容层连接重试与 daemon `accept` 超时防止启动阶段挂死。
- 不要把二进制/资源/测试视频留在 `/tmp`：重启会清空是小事，占用内存才是风险。

### 主菜单启动入口

**机制**（与 moonlight 一致，已从 shell 二进制字符串确认）：

- `shell`（Qt/QML 主菜单）扫描 **`/home/apps/<dir>/toc.txt`**，缺失时打印 `Missing name/icon/run entry in toc.txt`
- `toc.txt` 三行：`name=` 显示名、`icon=` 图标 png、`run=` 启动脚本
- 点图标 → shell 写 `/tmp/launch_cmdline.txt` 并退出 → `/home/steam/shell.sh` 的 `while` 循环 `eval` 执行该命令

**安装（持久化，重启不丢）**：

```sh
sh tools/steamlink-app/install.sh     # 在 WSL 里跑，自动部署全部文件
```

产物落点：

| 路径 | 内容 |
|---|---|
| `/home/apps/bilibili/toc.txt` | `name=Bilibili` / `icon=bilibili.png` / `run=bilibili.sh` |
| `/home/apps/bilibili/bilibili.png` | 图标（wiliwili 官方 256×256） |
| `/home/apps/bilibili/bilibili.sh` | 启动脚本（设 HOME/SL_DAEMON_PATH，`exec` 起 wiliwili，renice PE_Single_CPU） |
| `/home/apps/bilibili/bin/` | `wiliwili` + `slplayer_daemon` |
| `/home/apps/bilibili/resources/` | wiliwili 资源（约 13MB） |
| `/usr/local/bilibili/` | **HOME**，持久化保存 B 站登录态（否则每次重启要重扫码） |

**关键约束**：

- **透明层不能用环境变量全局打开**（重要）。borealis 补丁逐帧读 `SL_TRANSPARENT`，一旦在启动脚本里设置，**整个 UI 图层全透明**——首页/详情页没有视频层可透，背景就变成黑的。正确做法：启动脚本**不设**该变量，透明只在播放页需要，由兼容层在 `loadfile`/`stop` 时运行时切换。
- **可以用 `exec`**（与 moonlight 一致，省一个常驻 shell 进程）。安全性：`eval $cmd` 执行的是 `shell.sh` fork 出的子进程，`exec` 替换的是该子进程，不影响 `shell.sh` 的 while 循环；wiliwili 退出后循环继续，自动重新拉起主菜单。
- `HOME` 必须设到持久分区（`/usr/local/bilibili`），默认 `/tmp` 重启清空会丢登录态。
- 根分区 `/`（mtdblock9）可用 660MB，装完约 39MB；`/tmp` 只有 44MB 可用且重启清空，不要往那装。
- 卸载：`ssh root@<设备> "rm -rf /home/apps/bilibili /usr/local/bilibili"`；本安装不动 `shell.sh` / `rc.local` / moonlight。

**刷新主菜单**：`ssh root@<设备> "killall shell"`（`shell.sh` 循环会自动重建）。

> **注意**：`shell.sh` 由 `powermanager` 在开机时启动（powermanager 二进制内含 `/home/steam/shell.sh &`）。powermanager **不会**在运行期检测并重启 shell.sh——若手工 `kill -9` 掉 shell.sh 本身，需要手动再执行 `/home/steam/shell.sh` 才能恢复主菜单。

## 五、常用排查

```sh
ssh root@<device-ip> ps
ssh root@<device-ip> ls -l /tmp/ui.log
ssh root@<device-ip> tail -20 /tmp/ui.log   # 注意：管道/引号在设备端可能不生效
ssh root@<device-ip> cat /proc/<pid>/status
ssh root@<device-ip> cat /proc/<pid>/task/<pid>/wchan
ssh root@<device-ip> dmesg
```

- `gckOS_WaitSignal` 通常是正常 GPU/渲染等待
- 覆盖运行中的二进制前先 `killall`
- `/tmp` 是 tmpfs，重启清空
