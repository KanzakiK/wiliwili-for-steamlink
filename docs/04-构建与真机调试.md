# 构建与真机调试

## 一、环境

- 主机：Windows + WSL2（Ubuntu 26.04）
- SDK：`~/steamlink-sdk`（含 `setenv.sh`、`rootfs`、`toolchain`）
- 交叉编译器：`armv7a-cros-linux-gnueabi-gcc/g++`（GCC 9.2.0）
- 设备：`<device-ip>`，root / `<device-password>`

### 必须注意

- C++ 编译器依赖 `libmpfr.so.4`，必须设置：
  `export LD_LIBRARY_PATH=$HOME/steamlink-sdk/toolchain/lib:$LD_LIBRARY_PATH`
- CMake 用工具链文件：
  `-DCMAKE_TOOLCHAIN_FILE=$HOME/steamlink-sdk/toolchain/steamlink-toolchain.cmake`
- CMake 4.x 需要：`-DCMAKE_POLICY_VERSION_MINIMUM=3.5`
- 环境变量：`MARVELL_SDK_PATH`、`MARVELL_ROOTFS`
- CMake 识别交叉编译器：显式 `export CC=armv7a-cros-linux-gnueabi-gcc CXX=...`（仅设 `_COMPILER_INIT` 不够）

## 二、构建产物

### 1. 自编静态 libcurl（cpr 要求 ≥7.68，SDK 只有 7.26）

```sh
sh app/scripts/build-curl.sh
# 安装到 ~/steamlink-curl（curl 7.79.1，OpenSSL 1.0.1c + zlib）
```

### 2. wiliwili 整仓（当前使用）

```sh
sh tools/build-wiliwili.sh
# 源码固定来自本仓库 wiliwili/；borealis 来自 KanzakiK/borealis 的 steamlink-port 分支
# MPV 头文件 → ~/mpv-stub，默认构建目录 ~/build-wiliwili，产物 ~/build-wiliwili/wiliwili
# 资源在 ~/build-wiliwili/resources
```

脚本会设置 PATH/LD_LIBRARY_PATH/CC/CXX/MARVELL_*，检查 11 个 wiliwili 内源化标记和 3 个 borealis fork 标记，然后 CMake 配置 + make。`tools/patches/` 已清空，构建不再现场打 patch。可用 `SOURCE_DIR` 和 `BUILD_DIR` 覆盖源码/构建目录。

### 2c. libmpv 兼容层 + 播放子进程（进程隔离架构）

**两个独立二进制，分属两个进程：**

```sh
# 1) libmpv 兼容层（IPC 客户端，链进 wiliwili）
#    源码 tools/mpv-stub/mpv_stub.c，编译成 ~/mpv-stub/lib/libmpv.a
sh tools/build-wiliwili.sh    # 脚本第 2 步自动编译（gcc + -D_DEFAULT_SOURCE -pthread）
# 协议头 player/include/IpcProtocol.h 由脚本自动复制到 ~/mpv-stub/include/

# 2) 播放子进程（SlPlayer + IPC server）
export MARVELL_SDK_PATH=$HOME/steamlink-sdk MARVELL_ROOTFS=$HOME/steamlink-sdk/rootfs
export PATH=$HOME/steamlink-sdk/toolchain/bin:$PATH
export LD_LIBRARY_PATH=$HOME/steamlink-sdk/toolchain/lib:$LD_LIBRARY_PATH
cmake -S player -B ~/build-slplayer && cmake --build ~/build-slplayer -- -j4
# 产物：~/build-slplayer/{slplayer_test, slplayer_daemon, ipc_probe}
```

| 产物 | 作用 |
|---|---|
| `wiliwili` | UI 主进程，链接 `libmpv.a`（兼容层） |
| `slplayer_daemon` | 播放子进程，SlPlayer + Unix socket IPC server |
| `ipc_probe` | IPC 链路调试探针（不开 UI 直接验证 daemon 控制/事件面） |
| ~~`compat_test`~~ | 已封存到 `tools/deprecated-tests/`，默认不构建，禁止作为回归入口 |

> **旧测试程序已封存**：`compat_test` / `test-3.5c.sh` 已移到 `tools/deprecated-tests/`，不要再运行，也不要作为任何同步验收依据。真机出现过脏环境“有声音无画面”、干净环境“有画面无声音”，结果不能证明音视频同步。同步问题只在真实 wiliwili 播放页用 `--diag --sync-debug` 抓日志，并由用户确认听感/画面。

> **场景测试必须从统一入口触发（D27 落地后）**：用户通知“测试某场景”时，必须按 [08 设计](08-统一调试与日志系统设计.md) 使用 `tools/steamlink-app/debug.sh --content ... --scene ... --arg ...` 启动，并由它生成 run id、归档日志和 dmesg。第一版只支持启动期场景，没有运行中命令通道。从主菜单启动、手工写 `/tmp/launch_cmdline.txt`、进入应用后再手工操作，都不算按该场景测试；这类操作只能记为“手工探索”，不能作为场景回归或验收结果。若未走统一入口，必须明确说明并在日志中标注。

watchdog 阈值默认值：`SL_WATCHDOG_POLL_MS=500`、`SL_WATCHDOG_NOHB_MS=3000`、`SL_WATCHDOG_STALL_MS=1500`、`SL_WATCHDOG_GRACE_MS=2000`；设 `SL_WATCHDOG_DISABLE=1` 可临时关闭 watchdog（仅用于对照实验）。

真实内容/场景回归：旧 `--open-bv`、P0 seek、`SL_MEDIA_TAG` 测试 patch 已退休。用 `tools/steamlink-app/debug.sh --content video:<BV> --scene play|seek_forward|pause_resume|page_nav` 启动；controller 已内源化，只在这些环境变量存在时生效。`SL_SYNC_DEBUG=1` 继续输出音视频对齐阶段日志。

音频校准：`debug.sh --sync-offset-ms <ms>` 会写入 `SL_SYNC_AUDIO_OFFSET_MS`，正值让音频整体晚启动，负值让音频提前，默认 `0`。manifest 会记录 `sync_offset_ms`。`--sync-debug` 在启动点和启动 5 秒后输出 `frame/present/skip/audio_submit/queue` 等字段，其中 `drift` 基于队列推算的呈现位置，不是真实上屏时间戳。

卡顿提示：`debug.sh --health-force` 写入 `SL_HEALTH_FORCE=1`，用于强制触发一次 D22 提示链路；`--health-window-ms` / `--health-progress-ms` / `--health-net-grace-ms` 分别覆盖 `SL_HEALTH_WINDOW_MS` / `SL_HEALTH_PROGRESS_MS` / `SL_HEALTH_NET_GRACE_MS`。manifest 记录这些参数。强制运行时统一日志应同时出现 `][COMPAT]...health stall detected` 与 `][UI]...health hint shown`，并且不应出现 watchdog 或 `END_FILE(ERROR)`。

当前默认音频提交块为 `50ms`（48kHz / 2ch / S16 = 9600 字节）。不同清晰度下的残余偏差不一致，暂时不把 `10ms` 偏移设为默认；需要时用上面的校准参数做对照。

每次 debug 运行结束后，用 `bash tools/steamlink-app/check-debug-run.sh debug-runs/<run-id>` 校验归档：manifest 时间与大小、boot run id、CMD start/ok、统一日志前缀、UI/compat/daemon/player/audio 的 session 贯通、video/season 的 BV/cid/qn 三处一致、seek 的 CMD/EVT、content end、签名参数脱敏，以及 `dmesg.<scene>.start.txt` / `dmesg.<scene>.ok.txt` 边界快照。它只验证日志契约，不替代用户对画面、声音和同步的真机确认。

诊断开关（默认全部关闭，代码常驻源码，定位完成后只关开关不删代码）：

| 启动参数 | 环境变量 | 输出 |
|---|---|---|
| `--diag` | `SL_PLAY_DIAG=1` | 每秒输出播放 stage、位置、帧数、VPU 队列、下载窗口、read/base 偏移、pause/seek/bp 状态 |
| `--sync-debug` | `SL_SYNC_DEBUG=1` | 音视频对齐阶段日志 |
| `--http-debug` | `SL_HTTP_DEBUG=1` | SlHttp 读取等待、窗口淘汰细节 |
| `--stop-debug` | `SL_STOP_DEBUG=1` | stop / shutdown 各阶段日志 |
| `--diag-all` | 上述全部 | 全量诊断，只用于短时定位 |

`tools/steamlink-app/wiliwili.sh` 会消费这些启动参数，不把它们传给 wiliwili 本体；也可在 `/tmp/launch_cmdline.txt` 中直接用同名环境变量。诊断日志只写 `/tmp/wiliwili.log`，启动脚本每次启动会清空；长时间浸泡开启诊断时注意 tmpfs 占用。

**IPC 约定**（详见 `player/include/IpcProtocol.h`）：

- socket 路径默认 `/tmp/slplayer-ipc.sock`，可用环境变量 `SL_IPC_SOCKET` 覆盖
- 帧格式：4 字节小端长度 + 文本 payload（TAB 分隔字段）
- 控制面 `open/pause/resume/seek/stop/quit/volume/heartbeat`；事件面 `opened/playback_start/progress/paused/resumed/seeked/eof/error/fatal/heartbeat`
- 数据面（视频/音频）不经过 IPC，仍由 SLVideo/SLAudio 走硬件层

**启动时的环境变量**：

- `SL_DAEMON_PATH`：daemon 二进制路径（默认 `/tmp/slplayer/slplayer_daemon`）
- `SL_SYNC_NO_PROGRESS_MS`：SlPlayer 同步失败阈值，默认 `5000ms`、最小 `1000ms`。只看 `presentationMs` 高水位是否连续不推进；慢但在推进的视频一直等，不会按墙钟强制出声。失败时报 `Error` 并结束播放。旧 `SL_SEEK_AUDIO_FALLBACK_MS` 已移除。
- `SL_SYNC_AUDIO_OFFSET_MS`：有符号音频启动偏移，单位毫秒，默认 `0`。正值让音频晚于视频，负值让音频提前；统一入口用 `--sync-offset-ms` 传入。
- `SL_TRANSPARENT`：透明层开关，**由兼容层运行时 setenv/unsetenv 控制，启动脚本绝不要设**（设了会让整个 UI 全程透明，首页露出空视频平面变黑底）
- `/tmp/slplayer_vpu.lock`：VPU Dirty Flag，由 SlPlayer 自管；强杀会残留、正常退出会清除

## 三、部署到真机

> **⚠️ `/tmp` 是 tmpfs（内存盘），禁止把二进制/资源/测试视频长期放在里面。** 设备只有约 269MB 内存、无 swap；tmpfs 占用会直接减少可用内存。正式部署一律走 `/home/apps/wiliwili`（ext4 真实存储）。诊断方法与历史现场见 [03 踩坑](03-踩坑与经验.md) 和 [02 日志](02-开发进度日志.md)。

### 正式部署：一条命令

```sh
sh tools/steamlink-app/install.sh     # 在 WSL 里跑
```

脚本 6 步：校验本地产物 → 建目录 → 部署 toc/脚本/图标 → 部署二进制 → `tar` 部署 resources → **检查设备内存与 `/tmp` 占用**（超过 10MB 直接告警）。

> **部署前必须核对产物来源**：`install.sh` 只复制 `~/build-wiliwili` 与 `~/build-slplayer` 的现有产物，不会重新编译。先确认 `~/build-wiliwili/CMakeCache.txt` 中 `CMAKE_HOME_DIRECTORY` 指向当前仓库（默认 `/mnt/d/bilibili-steamlink`），必要时用新的 `BUILD_DIR` 重新运行 `tools/build-wiliwili.sh`。旧缓存曾指向 `/home/liufe/refs/wiliwili`，导致新源码与设备二进制不一致，统一日志缺少 `[UI] content start`。

### 标准 app 包

```sh
sh tools/steamlink-app/package.sh
```

脚本在 `dist/` 生成 `wiliwili-steamlink-<version>.tar.gz`（有 `zip` 时同时生成 `.zip`）。包内是标准 Steam Link 目录 `wiliwili/`，解压到 `/home/apps/` 后重启主菜单即可出现 `wiliwili` 图标；`INSTALL.txt` 包含安装说明。

### 临时验证单个新构建（不进主菜单入口）

即使只是临时验证，也**不要把文件放 `/tmp`**。放安装目录下的临时名，再用 `mv` 原子替换（避免覆盖正在执行的二进制）：

```sh
APP=/home/apps/wiliwili
scp ~/build-wiliwili/wiliwili root@<device-ip>:$APP/bin/wiliwili.new
sshpass -p <device-password> ssh root@<device-ip> \
  "chmod 755 $APP/bin/wiliwili.new && mv $APP/bin/wiliwili.new $APP/bin/wiliwili"
```

- 手动前台启动：`ssh root@<设备> "$APP/wiliwili.sh"`（会设好 HOME/SL_DAEMON_PATH）
- 程序退出后 Steam Link UI 会自动重启（`shell.sh` 的 while 循环）
- 日志：`ssh ... tail -f /tmp/wiliwili.log`（首行 `[boot]` 记的是启动时 `MemFree`/`Shmem`/`/tmp` 占用，**排查 OOM 先看这行**）
- 想边播边看内存曲线：`ssh ... "sh /tmp/memwatch.sh &"`，日志 `/tmp/memwatch.log`（脚本源在 `tools/steamlink-app/memwatch.sh`）

### 部署内容（wiliwili + 播放子进程）

统一走 `install.sh`：

```sh
sh tools/steamlink-app/install.sh
```

它把 `wiliwili`、`slplayer_daemon`、`resources/`、`toc.txt`、`wiliwili.png`、`wiliwili.sh` 全部装到 `/home/apps/wiliwili/`，并在最后打印设备内存与 `/tmp` 占用。

**部署注意事项**：

- 资源用 `tar czf` + `scp` + 设备端解包，不用 `scp -r resources/*`（设备 scp 对目录展开有问题）。
- 覆盖运行中的二进制先传 `xxx.new` 再 `mv`，避免 `Text file busy`。
- daemon 先启动并等待连接；兼容层连接重试与 daemon `accept` 超时防止启动阶段挂死。
- 不要把二进制/资源/测试视频留在 `/tmp`：重启会清空是小事，占用内存才是风险。

### 主菜单启动入口

**机制**（与 moonlight 一致，已从 shell 二进制字符串确认）：

- `shell`（Qt/QML 主菜单）扫描 **`/home/apps/<dir>/toc.txt`**，缺失时打印 `Missing name/icon/run entry in toc.txt`
- `toc.txt` 三行：`name=` 显示名、`icon=` 图标 png、`run=` 启动脚本
- 点图标 → shell 写 `/tmp/launch_cmdline.txt` 并退出 → `/home/steam/shell.sh` 的 `while` 循环 `eval` 执行该命令

**安装（持久化，重启不丢）**：

```sh
sh tools/steamlink-app/install.sh     # 在 WSL 里跑，自动部署全部文件
```

产物落点：

| 路径 | 内容 |
|---|---|
| `/home/apps/wiliwili/toc.txt` | `name=wiliwili` / `icon=wiliwili.png` / `run=wiliwili.sh` |
| `/home/apps/wiliwili/wiliwili.png` | 图标（wiliwili 官方 256×256） |
| `/home/apps/wiliwili/wiliwili.sh` | 启动脚本（设 HOME/SL_DAEMON_PATH，`exec` 起 wiliwili，renice PE_Single_CPU） |
| `/home/apps/wiliwili/bin/` | `wiliwili` + `slplayer_daemon` |
| `/home/apps/wiliwili/resources/` | wiliwili 资源（约 13MB） |
| `/usr/local/wiliwili/` | **HOME**，持久化保存 B 站登录态（否则每次重启要重扫码） |

**关键约束**：

- **透明层不能用环境变量全局打开**（重要）。borealis 补丁逐帧读 `SL_TRANSPARENT`，一旦在启动脚本里设置，**整个 UI 图层全透明**——首页/详情页没有视频层可透，背景就变成黑的。正确做法：启动脚本**不设**该变量，透明只在播放页需要，由兼容层在 `loadfile`/`stop` 时运行时切换。
- **可以用 `exec`**（与 moonlight 一致，省一个常驻 shell 进程）。安全性：`eval $cmd` 执行的是 `shell.sh` fork 出的子进程，`exec` 替换的是该子进程，不影响 `shell.sh` 的 while 循环；wiliwili 退出后循环继续，自动重新拉起主菜单。
- `HOME` 必须设到持久分区（`/usr/local/wiliwili`），默认 `/tmp` 重启清空会丢登录态。
- 根分区 `/`（mtdblock9）可用 660MB，装完约 39MB；`/tmp` 只有 44MB 可用且重启清空，不要往那装。
- 卸载：`ssh root@<设备> "rm -rf /home/apps/wiliwili /usr/local/wiliwili"`；本安装不动 `shell.sh` / `rc.local` / moonlight。

**刷新主菜单**：`ssh root@<设备> "killall shell"`（`shell.sh` 循环会自动重建）。

> **注意**：`shell.sh` 由 `powermanager` 在开机时启动（powermanager 二进制内含 `/home/steam/shell.sh &`）。powermanager **不会**在运行期检测并重启 shell.sh——若手工 `kill -9` 掉 shell.sh 本身，需要手动再执行 `/home/steam/shell.sh` 才能恢复主菜单。
