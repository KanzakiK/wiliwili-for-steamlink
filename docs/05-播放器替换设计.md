# 播放器替换设计（MPV → SLVideo）

> 本文档只写播放器替换的设计与接口契约。
> 任务状态在 [00-当前状态与任务.md](00-当前状态与任务.md)，实现过程、复核和真机数据在 [02-开发进度日志.md](02-开发进度日志.md)。

## 一、总体边界

- wiliwili 的 UI/业务层只使用 `MPVCore` 的 C++ 接口和 `MPVEvent`，不直接调用 libmpv。
- 直接依赖 libmpv 头文件的只有 `wiliwili/source/view/mpv_core.cpp` 和 `include/view/mpv_core.hpp`；因此用 libmpv 兼容层替换实现即可保持 wiliwili 源码零改动。
- 兼容层以 IPC 客户端形态控制独立 `slplayer_daemon`；SlPlayer 在 daemon 内驱动 SLVideo/SLAudio。
- 控制面（loadfile/pause/seek/stop/属性/事件/心跳）走 Unix socket；视频帧和 PCM 不过 IPC，仍由硬件层输出。
- 不引入 mpv 本体；`mpv_render_context_*` 保持 no-op，视频由 SLVideo 直接上屏。

三层契约：

| 层 | 职责 |
|---|---|
| wiliwili UI / MPVCore | 表达目标状态，消费 mpv 事件和属性；保持上游逻辑不变 |
| libmpv 兼容层 | 翻译 mpv 命令/属性/事件；维护事件队列、观察表、文件代次和请求号；管理 daemon 与 watchdog |
| IPC / daemon / SlPlayer | 执行命令，Reporting 已完成的当前状态； daemon 只透传带代次的事件，SlPlayer 产生唯一时间与播放状态 |

## 二、UI 依赖契约

### 1. 生命周期与操作

| 接口 | 调用方 | 语义 |
|---|---|---|
| `setUrl(url, extra, "replace")` | `BasePlayerActivity::updateVideoLink` | 首次打开、换清晰度、换集 |
| `setBackupUrl(url, extra)` | 同上 | mpv `append` 语义，只入备用源队列，不立即播放 |
| `resume()` / `pause()` | `VideoView` | 播放/暂停 |
| `seek(int)` / `seekRelative(int)` / `seekPercent(double)` | `VideoView` | 绝对秒、相对秒、百分比 |
| `stop()` | `VideoView` | 退出播放页，释放播放器并恢复不透明 UI |
| `setSpeed(double)` / `setVolume(...)` | `VideoView`、`PlayerSetting` | 倍速、音量 |
| `reset()` | 视频详情/直播 | 换源前清空状态并发 `RESET` |
| `restart()` | 设置页 | 重建播放器并重新取流 |

高频状态：`isValid()`、`isPaused()`、`isPlaying()`、`isStopped()`、`getVolume()`、`getSpeed()`、`getPlaybackTime()`、`getCacheSpeed()`。

### 2. 属性

UI/DanmakuCore/SubtitleCore 直接读取：`duration`、`playback_time`、`video_progress`、`video_speed`、`video_paused`、`video_stopped`、`video_seeking`、`video_eof`、`percent_pos`、`cache_speed`、`volume`、`hwCurrent`、`filepath`。

观察表使用 mpv 原名和编号 1～21；编号 8、9 在上游源码中注释，实际启用 19 项：

`core-idle`(FLAG)、`eof-reached`(FLAG)、`duration`(INT64)、`playback-time`(DOUBLE)、`cache-speed`(INT64)、`percent-pos`(DOUBLE)、`paused-for-cache`(FLAG)、`speed`(DOUBLE)、`volume`(INT64)、`pause`(FLAG)、`playback-abort`(FLAG)、`seeking`(FLAG)、`hwdec-current`(STRING)、`path`(STRING)、`brightness`/`contrast`/`saturation`/`gamma`/`hue`(DOUBLE)。

属性初值必须随 observe 注册回放；`speed` 尤其关键，因为 wiliwili 的 `video_speed` 默认 0，滚动弹幕播放分支会乘以该值。

### 3. 事件

| 事件 | 订阅方 | 用途 |
|---|---|---|
| `START_FILE` | VideoView | 开始加载，隐藏 OSD |
| `MPV_LOADED` | VideoView | 文件加载完成，触发续播 seek |
| `LOADING_START` / `LOADING_END` | VideoView、DanmakuCore | 加载圈/缓冲提示 |
| `UPDATE_DURATION` | VideoView | 设置总时长 |
| `UPDATE_PROGRESS` | VideoView、PlayerBaseActivity | 进度条、15 秒历史、链接过期刷新 |
| `MPV_PAUSE` / `MPV_RESUME` | VideoView | OSD 与播放图标 |
| `MPV_STOP` | VideoView | 停止/错误 |
| `MPV_FILE_ERROR` | LivePlayerActivity | 直播错误 |
| `END_OF_FILE` | VideoView、PlayerBaseActivity | 自动连播/重播 |
| `CACHE_SPEED_CHANGE` | VideoView | 缓冲速度 |
| `VIDEO_SPEED_CHANGE` | VideoView、DanmakuCore | 倍速显示/弹幕速度 |
| `VIDEO_MUTE` / `VIDEO_UNMUTE` | VideoView | 音量图标 |
| `RESET` | VideoView、DanmakuCore、SubtitleCore | 清空进度、弹幕、字幕 |
| `RESTART` | PlayerBaseActivity | 重建后重新取流 |

事件时序：

1. `loadfile` → `START_FILE` → `FILE_LOADED` → `PLAYBACK_RESTART`。
2. 进度：`playback-time` 变化 → 整数秒变化才发 `UPDATE_PROGRESS`。
3. 缓冲：`paused-for-cache=true/false` → `LOADING_START/LOADING_END`。
4. seek：`seeking=true` → `LOADING_START`；seek 完成 → `playback-time` 更新 + `seeking=false` → `PLAYBACK_RESTART/LOADING_END`。
5. 结束：先 `eof-reached=true`，再 `end-file(reason=EOF)` → `END_OF_FILE`。
6. 错误：`end-file(reason=ERROR)` → `MPV_STOP` + `MPV_FILE_ERROR`。
7. pause/resume：`pause` 与 `core-idle` 同步；`core-idle` 驱动 `MPV_IDLE → refreshToggleIcon()`。

### 4. 可降级接口

首期可 no-op 或返回常量：`setAspect`、`setMirror`、亮度/对比度/饱和度/伽马/色相、`setHwdecCopyMode`、`setShader`/`clearShader`、`showOsdText`、诊断页的 `getString/getDouble/getInt/getNodeMap`。

## 三、播放源形态

`BasePlayerActivity::updateVideoLink` 会产生三种源：

1. **DASH（首选）**：视频 `base_url` + 音轨 `base_url`/`backup_url` 列表；`extra` 携带 referrer、network-timeout、start、end、audio-file（可多条）等。
2. **FLV 单段**：`setUrl(durl[0].url, start, end)`。
3. **FLV 多段**：`edl://...` 与 `!delay_open,media_type=video/audio`、`length=` 参数；后续支持。

API 结果可先发 `REAL_DURATION`，使播放器首帧前显示进度条；最终时长仍以 format/stream 为准。

## 四、兼容层与 IPC

### 1. mpv API 边界

兼容层导出 22 个唯一 `mpv_*` API：生命周期（`create/initialize/terminate_destroy`）、版本/错误字符串、命令（`command_async/command_string`）、选项、属性（observe/get/get_string）、事件（wakeup/wait）、内存（`free/free_node_contents`）、渲染上下文 create/update/callback/render/report_swap/free。

静态链接构建中 `mpv_core.hpp` 直接把 wrapper 映射到 `mpv_*` 符号，因此兼容层就是替换 `tools/mpv-stub/mpv_stub.c`。

### 2. 命令映射

| wiliwili 命令 | mpv 语义 | 兼容层处理 |
|---|---|---|
| `loadfile <url> replace <extra>` | 播放该文件 | 解析 extra，开启透明，发送 `open` |
| `loadfile <url> append <extra>` | 只加入播放列表 | 入备用源队列（≤8），不触发播放 |
| `playlist-clear` | 清空列表但保留当前播放项 | 只清备用队列，不下发 stop |
| `stop` | 停止并清空 | 下发 stop，恢复不透明 UI |
| `set pause yes/no` | 暂停/恢复 | 下发 pause/resume，同步 pause 与 core-idle |
| `seek <v> absolute` | 绝对秒 | 换算并钳制后下发 `seek` |
| `seek <v> relative` | 相对当前呈现时间 | 兼容层用 daemon 上报时间换算成绝对秒 |
| `seek <v> absolute-percent` | 百分比 | 用 duration 换算成绝对秒 |
| `set video-margin-ratio-*` / `panscan` | 画面边距 | no-op；SLVideo 全屏输出 |

### 3. IPC 帧

传输：4 字节小端长度 + TAB 分隔文本 payload。统一信封：

```text
<name>\t<file_generation>\t<request_id>\t<args...>
```

- `file_generation`：每次 `loadfile replace`、备用源实际切换、watchdog 回放递增；`append` 入队不递增。
- `request_id`：每个命令递增；完成事件原样回传，旧 seek 完成不得覆盖新目标。
- daemon 丢弃 generation 不匹配的命令/事件，兼容层过滤过期文件事件。

控制命令：`open/pause/resume/seek/stop/volume/heartbeat/quit`。
事件：`opened/playback_start/progress/paused/resumed/seeked/eof/error/fatal/heartbeat`。
心跳事件携带 `lastFrameTimeMs/stage/playing/inTransition/videoFrames/currentPaused/targetPaused/seeking/workerAlive`。

### 4. 状态所有权

| 信息 | 事实源 | 传播 |
|---|---|---|
| 当前呈现时间 | SlPlayer `position_` | `Progress`/`Seeked` → `playback-time`/`percent-pos` → UI |
| 目标暂停态 | UI `set pause` | 兼容层 → IPC → SlPlayer 目标字段 |
| 当前暂停态 | SlPlayer 播放线程 | 完成 flush/首帧重建后 → `Paused/Resumed` → `pause` 属性 |
| 目标播放位置 | `seek` 命令 | 兼容层换算绝对秒 + request id → daemon |
| 当前播放位置 | daemon 上报 | `progress/seeked` 覆盖兼容层镜像，watchdog 恢复只读该值 |
| 文件代次 | 兼容层 | 随命令/事件传播，隔离旧文件状态 |
| 工作线程活性 | SlPlayer 原子快照 | heartbeat 上报，watchdog 判定 |

## 五、播放器语义契约

### 1. 标准序列

| 场景 | 必须行为 |
|---|---|
| 冷启动 | 新文件重置状态；`START_FILE` → `FILE_LOADED`；首帧稳定后才 `PLAYBACK_RESTART` 与 LOADING_END |
| 续播打开 | `start=` 是初始目标；FILE_LOADED 后等价 seek 去重；接近片尾按 wiliwili 原行为 seek(0)；最终 playback-time 取 daemon 实际值 |
| pause/resume | 命令先更新目标态；flush/定位/首帧完成后才更新当前态并发属性事件 |
| seek | absolute/relative/percent 统一成绝对媒体时间；内部关键帧预读与窗口重启对外不可见；完成后更新 playback-time 并发 PLAYBACK_RESTART |
| EOF | 先 `eof-reached=true`，再 `END_FILE(reason=EOF)`，保证 wiliwili 的 END_OF_FILE 条件成立 |
| 连续文件 | 每个文件代次独立重置时间、暂停、seek、音频基准和事件队列；旧代次事件不得进入新文件 |

### 2. 单一时间真相

- `playback-time`、`video_progress`、续播位置和弹幕时钟只消费 daemon 上报的当前呈现时间。
- 兼容层属性缓存只用于分发 `PROPERTY_CHANGE`，不再根据 `lastOpenCmd`、关键帧 PTS 或本地墙钟推算 UI 时间。
- SLVideo `GetQueuedVideoMS()`、下载字节位置、关键帧 PTS、音频 submittedMs 仅用于到达目标状态，不能直接冒充 UI 时间。

### 3. 目标态与当前态分离

- 命令入口只更新目标态和 generation。
- 播放线程完成 flush、Range/关键帧定位、首帧重建、音频对齐后才更新当前态和可观察时间。
- 事件队列只发布当前态变化；属性变化与 `MPV_PAUSE`/`MPV_RESUME` 从同一快照生成。
- 新命令以最新目标为准；旧 generation/request id 的完成路径不得覆盖新目标。

### 4. 续播优先级

1. `loadfile` extra 的 `start=` 是新文件初始目标。
2. FILE_LOADED 后 `lastPlayedPosition` 的 seek 是确认/修正；等价时只回执，不重复重建 VPU。
3. 距结尾 ≤5s 的 seek(0) 按 wiliwili 原行为执行。
4. 用户显式 seek/进度条拖动优先级高于续播目标。
5. 切集、换清晰度、EOF 下一集必须清空上一文件目标。

### 5. seek 与 VPU 重建

- 用户主动 seek 仍需 `FreeStream/CreateStream`：SLVideo 没有 flush 接口，清理播放队列只能通过重建 stream。
- 新流尚未提交帧时的 start seek、暂停 flush 已完成后的恢复 seek，只重新定位 demuxer，不重复重建 stream。
- 连续重建之间至少留 400ms，让 VPU/SHM 连续块回收；单次 seek 不受该间隔影响。
- 窗口外或大步快进通过 HTTP Range 重新请求，不用等待 8MB 滑动窗口顺序追上。

### 6. 音频基准

- 暂停：先 flush 视频队列，再停音频。
- 恢复：以暂停请求时间为目标，从关键帧提交后按实测上屏延迟安排音频启动。
- 续播起播未测到延迟时，队列稳定后无条件记录一次 `measuredVideoLatencyMs`；后续 seek 使用“目标时间 + 实测上屏延迟 + 关键帧差值”的精确对齐。
- 兜底音频启动必须双向对齐：`presentationMs > audioBaseMs` 时跳过音频，`presentationMs < audioBaseMs` 时延迟音频；带 `start=` 的新文件（切清晰度）常见后者，不能把负偏移截成 0。统一通过 `scheduleStart(delayMs, skipMs)` 表达。
- “视频已上屏”分支保留为冷启动测延迟和兜底，不作为 seek 主路径。

### 7. heartbeat

- heartbeat 代表播放工作线程存活，而非仅 IPC 主循环存活。
- 只读 atomic 快照，不进入播放线程持有的锁，不调用 stats()。
- 播放线程退出或长时间无首帧时，心跳快照必须反映不可用；watchdog 只负责判定与上报，恢复动作由兼容层控制。

## 六、渲染

- SLVideo 的 stream 没有目标矩形接口；硬解视频只能全屏输出，播放页必须使用 `PLAYER_AUTO_FULLSCREEN`。
- 视频在硬件视频层；GUI/弹幕在 GL 层。透明方案要求 SDL/EGL alpha=8，播放页 clear alpha=0，首页/详情页保持不透明。
- `SL_TRANSPARENT` 由兼容层在 loadfile 时 setenv、stop/EOF/错误/退出时 unsetenv；不写入启动脚本。
- 不引入自定义详情页封面占位或“点击封面进全屏”流程；保持 wiliwili 原生播放页行为，避免改布局/Activity 逻辑。
- 清晰度/分 P 切换沿用 wiliwili 原生流程，不增加播放胶水之外的状态。

## 七、音频管线

- SLAudio sink 固定 48000Hz / stereo / S16，20ms 帧（3840 字节）。
- B 站 AAC 解码后统一重采样到 48kHz；不保留非 48k 源采样率透传分支。
- 解码输出可能是 FLTP（AAC/AC3/EAC3）或 S16/S32（FLAC 等），swr 保留通用格式转换；多声道下混到 stereo。
- `AudioPipeline::start()` 同步创建 SLAudio stream 并有限重试；失败则静音，不阻塞视频主循环。

## 八、资源与稳定性策略

- Linux 内存、tmpfs/anonymous 内存、GPU/VPU shm 池是不同账本；不能用 MemFree 单独判断 VPU 可用性。
- VDEC 小块分配失败由减少 stream 重建 + 400ms 重建间隔处理；UI/GPU 51.84MB 大块分配失败另按 D14 取证。
- SPS 改写默认关闭：`refs 7→4` 会造成花屏；`SL_SPS_REWRITE=1` 只做实验，VPU/SHM 稳定性不依赖改片源参数。
- 图片请求尺寸由构建补丁按 Steam Link 显示尺寸收敛，不改 wiliwili 布局/样式；用于降低 JPEG 解码峰值和 GPU 纹理缓存占用。
- 不依据 PSV 的 480P/720P 上限给 Steam Link 统一降清晰度；是否降级按实际 qn/codec/refs、SHM 峰值和 OOM 现场决定。
- Steam Link 能力卡位：视频最高 1080P60（qn≤116），4K/HDR/8K 不提供给用户选择；FLV/MP4 支线的 720P 内部编号 `192` 是兼容档，必须保留。音频只提供 AAC High/Medium/Low（`30280/30232/30216`）。这些约束通过构建补丁收敛 wiliwili 选项与清晰度菜单，不改 UI 布局/样式，也不改播放胶水。
- 编码固定 AVC/H.264（`codecid=7`），不向用户暴露 HEVC/AV1；播放器设置中的亮度、对比度、饱和度、伽马、色相及重置项对 SLVideo 硬解不生效，统一隐藏；播放页 OSD 倍速入口同样隐藏。隐藏时还要同步清理焦点可达性，避免不可见控件继续参与焦点导航。两者同样只由构建补丁处理。
- 日志：每文件打印一次 oid、qn、音轨数、时长、分辨率、帧率和 SPS 策略；测试入口额外记录 BV tag；不打印整条签名 URL。

## 九、Kodi 参考结论

- `SLVideo_CreateStream(context, H264, lowLatency=false)`，设置目标帧率；`BeginFrame → WriteFrameData → SubmitFrame` 每步检查返回值。
- Kodi 的 `Flush() = Close() + Open()` 与本项目重建 stream 一致；送帧失败按“丢帧 + 上报错误”处理，不阻塞主循环。
- 视频延迟使用 `GetQueuedVideoMS()`；音频延迟使用 `GetQueuedAudioSamples / channels / rate`。
- Kodi/Moonlight 都不设置 `SLVideo_SetStreamTargetBitrate()`；本项目是否移除该固定值必须按 D14 时间线取证，不直接照搬。
- Moonlight 的 `lowLatency=1` 仅适用于受控 I/P 流，不能直接类比 B 站 high profile、B 帧、高 refs 点播流。
