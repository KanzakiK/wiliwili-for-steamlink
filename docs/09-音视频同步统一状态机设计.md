# 音视频同步统一状态机设计（D28）

> 本文只定义 D28 同步架构、接口、实施与验收契约。任务状态只写在 [00](00-当前状态与任务.md)，实施过程和真机证据只写在 [02](02-开发进度日志.md)，构建与调试命令见 [04](04-构建与真机调试.md)。

## 0. 目标与非目标

把首播、续播、快进快退、暂停恢复、清晰度切换、硬卡顿自动降级、watchdog replay、CDN failover 等所有中断音视频时间线的操作，统一到一个状态机。每个入口只提供原因和精确目标，入口耗时只诊断、不参与同步计算。

非目标：不改变 D21/D22 的 VPU 健康检测范围、自动降级范围或 Toast 文案；不把同步失败静默降级为“先出声再纠偏”；正常路径不依赖固定经验偏移；不规定真实上屏时间戳的 SDK 改造；不恢复旧测试脚本作为验收依据。

## 2. 已拍板决策

以下决策均为最终口径，不再设“待拍板”章节。

| 编号 | 决策 |
|---|---|
| D28-1 | 每次时间线不连续都创建 `SyncEpoch`，epoch 是同步生命周期的唯一单位。 |
| D28-2 | 内部媒体时间统一为 `int64` 微秒；`target_us` 是唯一权威起点。旧秒字段只是输入格式，compat 边界必须归一化。 |
| D28-3 | 所有 restart 都经过 compat 的 `beginEpoch()`；场景不得自行计算音频偏移或直接调用音频启动。 |
| D28-4 | 起点在 `beginEpoch()` 时冻结；入口耗时只记录，不进入同步公式。 |
| D28-5 | 音频启动点只由媒体时间判断：首帧已提交、队列稳定、音频 seek 完成且 `audioQuiet`，再按画面位置决定等待或跳过。 |
| D28-6 | 墙钟只用于 PCM 调度和存活超时，不能代替媒体时间判断画面位置。 |
| D28-7 | `SL_SYNC_AUDIO_OFFSET_MS` 只作诊断，默认 0；正式验收必须关闭。 |
| D28-8 | 同步失败显式结束，不允许“先出声再纠偏”。 |
| D28-9 | 代码与计划冲突时停止实施，由用户拍板后更新本文，不允许实现时临时改口径。 |
| D28-10 | `firstFramePtsAfterSeekMs`、`seekDisplayTargetMs`、`measuredVideoLatencyMs` 全部降级为诊断字段，不进入求解器。 |
| D28-11 | 起播同步与 `RUNNING` 纠偏分原子步骤实施；基线阶段关闭自动纠偏。 |
| D28-12 | 设计契约未关闭前不进入 D28-S02；所有实施以第 9 节为唯一任务清单。 |
| D28-13 | 原子步骤使用 `D28-S01～D28-S11`，不与决策编号共用。 |
| D28-14 | compat 是 epoch 唯一权威所有者，负责创建、递增、冻结目标、写 `SYNC_BEGIN` 和全部 `SYNC_END`；SlPlayer 只执行本地状态机并上报阶段。 |
| D28-15 | 所有新 IPC/日志时间字段使用 `*_us`；兼容秒值必须归一化到 `target_us`，不得成为第二权威。 |
| D28-16 | SlPlayer 是 `vpu_state` 唯一计算方，随 heartbeat 上报；D22/D28 共用，不在 compat 侧重复推导。 |
| D28-17 | SlPlayer 不能直接控制 VPU；pause/seek/resume 必须由状态机和 ack 管理，不依赖调度时序或硬件队列自然排空。 |

沿用 `SL_CMD_META` 承载 `epoch/target_us/sync_reason`，不新增 `beginEpoch` IPC。pause 采用 `requestSeek(target_us)`，音频线程以 `finishSeek` ack 作为 `audioQuiet` 唯一确认；resume 不二次 seek。旧 `open.start`、loadfile extra `start` 和 debug `target/delta` 必须至少支持毫秒精度，并在 compat 边界转成整数微秒。

## 3. 架构所有权与接口边界

| 层 | 所有权与责任 |
|---|---|
| UI / Activity | 表达用户意图和内容身份；上游秒值只作为兼容输入，不定义 D28 同步目标。 |
| compat | `beginEpoch()` 唯一调用方；冻结 `target_us`；创建 epoch；写 `SYNC_BEGIN/SYNC_END`；管理 watchdog 强杀后的终态；归一化所有旧时间字段。 |
| SlPlayer | 执行 compat 已创建的 epoch；控制视频 demux、VPU stream 生命周期和音频启动；上报 `SL_EVT_SYNC`；不创建/关闭 epoch；不写 `SYNC_END`。 |
| AudioPipeline | 音频 seek、预缓冲、启动点应用、`audio_media_us` 记账；不感知快进、降级等业务原因。 |
| D22 / watchdog | 消费 heartbeat 中的统一 `vpu_state`；hard/STALL 时由 watchdog 恢复进程，D28 暂停纠偏。心跳丢失和 worker 死亡由 compat 独立兜底。 |
| VPU | SlPlayer 只能请求 FreeStream/CreateStream/SubmitFrame，不能直接控制呈现时钟；所有状态变化必须由显式 ack 和日志确认。 |

具体接口改动：

- `VideoView::genExtraUrlParam` 提供整数微秒重载，loadfile extra 写 `start_us/end_us`；旧 `start/end` 仍可输入，但只作兼容。
- `updateVideoLink()` 使用当前 `position_us`，不得读取 `MPVCore::video_progress` 整数秒作为续播目标。
- `SourceSpec.startSeconds` 改为 `start_us/end_us`，只在 FFmpeg `av_rescale_q()` 边界转换为 FFmpeg timestamp；IPC、状态机和日志不得退化回秒。
- `AudioPipeline` 只暴露音频 seek、预缓冲长度、启动点应用和已提交/排队量查询；不感知快进、降级或 pause 的业务原因。

compat 的 epoch 注册表至少保存：`epoch_id`、`reason`、`target_us`、`target_source`、session/generation/request、当前状态、终态写入位置。watchdog 强杀后 compat 必须为旧 epoch 写 `error/superseded`，再由新 epoch 接管。

## 4. 数据模型与时间单位

### 4.1 Epoch 字段

| 字段 | 含义 |
|---|---|
| `epoch_id` | compat 创建、跨 daemon 重启仍有效的整数 ID。 |
| `reason` | `open` / `history_resume` / `seek` / `pause_resume` / `quality_change` / `auto_downgrade` / `watchdog_replay` / `failover` / `next` / `live_connect` / `drift_reanchor`。 |
| `target_us` | 当前 epoch 的权威媒体起点。 |
| `target_source` | 目标来源，如 `pause_command`、`watchdog_progress`、`user_seek`。 |
| `content_key` / `session` / `generation` / `request_id` | 与 D27 日志一致的内容与命令身份。 |
| `decision_wall_ms` / `prepare_start_wall_ms` | 入口耗时诊断，不进入媒体公式。 |
| `first_frame_pts_us` | 首帧 PTS，诊断字段。 |
| `queue_stable_us` / `audio_seek_done_us` | 门禁达成的墙钟时间。 |
| `audio_start_wall_ms` | 第一段可听 PCM 的墙钟时间。 |
| `audio_media_us` | 本次 epoch 已消费的音频媒体时间。 |
| `queued_audio_media_us` | 已提交未播放 PCM 折算回的媒体时长。 |
| `compensation_ppm` | PCM 补偿比例，无补偿为 0。 |
| `quiet_ack` | `finishSeek` / `silent` / `legacy`。 |
| `quiet_seq` | `finishSeek` 对应的音频 seek 序号。 |
| `skip_us` | 为使音频内容从 `target_us` 开始而跳过的预缓冲长度。 |
| `state` / `sync_mode` | 当前状态；本次运行的检查模式。 |

诊断但不参与求解：`first_frame_pts_us`、`seek_display_target_us`、`measured_video_latency_us`。

manifest 使用 `sync_mode`：`legacy` / `mixed_compat` / `mixed_daemon` / `d28`。检查脚本按模式选择契约，不能用 D28 契约判 legacy/mixed run FAIL。

### 4.2 时间单位契约

- 新时间字段统一 `*_us`，保存整数微秒；墙钟诊断字段使用 `wall_ms`，不得与媒体时间混用。
- `target_us`、`start_us`、`end_us`、`position_us`、`skip_us`、`drift_us` 一律为整数微秒。
- 兼容输入包括 `open.start`、loadfile extra `start/end`、debug `target/delta`。整数秒仍可接受，但 compat 必须解析成 `target_us`，旧字段不再作为独立权威。
- 兼容字符串可用小数秒，至少保留毫秒精度，建议 6 位小数；必须由同一 `target_us` 生成，不得独立反推。
- `SL_CMD_META.target_us` 是 D28 路径唯一权威。`SL_CMD_OPEN` 可同时携带 `start_us/end_us` 和旧 `start/end`；旧字段只供旧 daemon 回退。
- `SL_CMD_SEEK` 增加 `target_us`；旧秒级 seek 只在无新字段时回退。
- UI 播放进度、历史进度、debug 目标、watchdog 恢复位置、CDN failover 位置和自动降级位置都在 compat 边界转成 `target_us`。

### 4.3 时钟定义

- `presentation_us`：估算的当前画面呈现媒体时间，当前为 `maxSubmittedFramePtsUs - videoQueuedUs`，不是真实上屏时间戳；日志必须标为估算。
- `audio_content_us`：`target_us + skip_us + audio_media_us - queued_audio_media_us`。无补偿时 `audio_media_us` 等于已提交 PCM 的媒体时长。
- `wall_ms`：单调墙钟，只用于调度和存活超时。

SDK 以后提供真实上屏时间戳时，只替换 `presentation_us` 来源，不改状态机和 `target_us` 契约。

## 5. 统一状态机

```text
IDLE
  | beginEpoch(reason, target_us, identity)
  v
PREPARING
  | 准备命令已下发
  v
WAIT_FIRST_FRAME
  | 首个视频帧成功 SubmitFrame
  v
WAIT_QUEUE_STABLE
  | 视频队列稳定 && 音频 seek 完成 && audioQuiet
  v
WAIT_TARGET_POSITION
  | presentation_us >= target_us
  v
SCHEDULED
  | scheduleStart 已下发，等待第一段可听 PCM
  v
RUNNING
  | 周期性采样并进入闭环
  v
END / SUPERSEDED / FAILED
```

`RUNNING` 内部闭环：

```text
CONVERGING
  | 连续有效样本落在死区
  v
CONVERGED
  | 连续同向样本超过微纠偏阈值且 vpu_state=STABLE
  v
CORRECTING
  | 补偿后进入死区 -> CONVERGED；不收敛 -> 请求 drift_reanchor 或 FAILED

vpu_state=PRESSURE/STALL -> SUSPENDED_VPU，禁止纠偏并交由 D22/watchdog
vpu_state 恢复 STABLE 且原 epoch 有效 -> CONVERGING
```

`drift_reanchor` 是创建新 epoch 的事件，不是独立状态。compat 创建新 epoch 后，旧 epoch 写 `SYNC_END status=superseded`。watchdog 强杀与自动降级同时发生时，compat 只保留一个赢家；另一个 epoch 写 `superseded`，不能两个都 open。

### 5.1 状态动作

| 状态 | 进入动作 | 离开条件 |
|---|---|---|
| `PREPARING` | compat 递增 epoch；旧 epoch 事件失效；旧音频阻断；冻结 `target_us`；视频/音频定位和重建 | 准备命令已下发，进入 `WAIT_FIRST_FRAME` |
| `WAIT_FIRST_FRAME` | 记录 `first_frame_pts_us`；watchdog 挂起 | 首个视频帧提交 |
| `WAIT_QUEUE_STABLE` | 记录 `queue_stable_us`、`audio_seek_done_us`；计算 `skip_us` | 队列稳定、音频 seek 完成且 `audioQuiet`；无音频时直接 `SCHEDULED` |
| `WAIT_TARGET_POSITION` | 画面越过目标则计算 `skip_us`；未越过则等待 | 调用统一 `scheduleStart` |
| `SCHEDULED` | 等待音频线程应用启动点 | 第一段可听 PCM 提交；无音频时按 silent 模式进入 `RUNNING` |
| `RUNNING` | 周期性采样并执行第 7.2 节闭环 | 新 epoch、正常结束或错误 |

起播等待失败只看媒体位置是否推进：呈现高水位在 `SL_SYNC_NO_PROGRESS_MS` 内不动进入 `FAILED`。`RUNNING` 的纠偏失败按第 7.2 节判断，不复用起播条件。入口等待多久不算失败。

入口耗时包括 API 请求、UI 页面切换、Range 建连、daemon fork、VPU Free/Create 和音频 stream 重建；这些只写 `wall_*` 诊断字段，不能加到媒体目标上。

直播跳过 `WAIT_TARGET_POSITION`，`target_us=0` 表示流起点；无音频时 `quiet_ack=silent` 并走完整 epoch 生命周期。

## 6. 统一起点与入口映射

唯一权威入口在 compat：

```text
beginEpoch(reason, target_us, content_key, session, generation, request_id, flags)
```

必须完成：

1. compat 创建并递增 `epoch_id`。
2. compat 冻结 `target_us`，后续进度上报不得改写。
3. 旧 epoch 失效，旧 seek 完成、旧 audio start 和旧 watchdog replay 全部丢弃。
4. 立即阻断旧音频；新音频在 `SYNC_START` 前不得提交可听 PCM。
5. 视频和音频定位到同一 `target_us`；VPU 重建最多一次。
6. loadfile 后不得隐式插入等价续播 seek；目标未知时推迟 loadfile 或停在 `PREPARING`。
7. compat 写 `SYNC_BEGIN`，入口耗时只记录。

`beginEpoch()` 成功后，旧流进度和音频提交不再定义当前时间线；UI 显示和 health 判据进入 transition。旧流只能保持最后一帧可见，不能继续推进 `target_us`。入口耗时不得加到媒体目标上。

### 6.1 目标来源

| 场景 | 权威 `target_us` 来源 | 要求 |
|---|---|---|
| 冷播无历史 | `0` | 新 open，创建 epoch。 |
| 历史续播 | 历史接口位置归一化 | 只在 meta 传一次；取消 `MPV_LOADED` 后二次 seek。 |
| 快进/快退 | 请求位置归一化；相对量先算绝对微秒 | 方向不进入同步公式。 |
| 暂停恢复 | pause 命令接受时冻结的呈现位置 | resume 不读取 UI 整数进度，不二次 seek。 |
| 手动切清晰度 | 切换命令接受时的精确位置 | 新 loadfile 带 `target_us`，不截断。 |
| 自动降级 | hard 判定时 compat 精确进度 | 与 watchdog replay 共用入口。 |
| watchdog replay | compat `resumePosition` | 新 daemon 后创建 epoch，旧 session meta 复用但 epoch 更新。 |
| CDN failover | 错误发生时的精确呈现位置 | 不沿用原始 `open.start`。 |
| RUNNING 纠偏失败 | 当前 `presentation_us` | `reason=drift_reanchor`，只创建新 epoch。 |
| EOF 自动续播 | `0` | 新内容、新 session、新 epoch。 |
| 直播重连 | `0` | 创建 epoch，跳过目标位置等待。 |

### 6.2 pause 的 audioQuiet 契约

pause 命令被接受时立即冻结 `target_us`，SlPlayer 调用 `requestSeek(target_us)`。音频线程完成 seek、释放/重建 stream 并清掉硬件 PCM 后回 `finishSeek` ack，才允许写 `audio_quiet=1`，并记录 `quiet_ack=finishSeek`、`quiet_seq`。

UI 可以立即反馈暂停，但 `SYNC_PREPARED` 必须等 ack。resume 复用冻结目标；audioQuiet 已完成时不得二次 seek。仅 `setPaused(true)` 或自然排空不满足契约。

## 7. 统一求解器与闭环控制

### 7.1 起播求解器

输入：`target_us`、`presentation_us`、`video_queue_us`、`audio_preroll_us`、`audio_queue_us`、`audio_seek_done`。

规则：

1. 只有 `videoStarted && queueStable && audioSeekDone && audioQuiet` 后允许求解。
2. `presentation_us >= target_us` 时，`skip_us = presentation_us - target_us`，不超过可用预缓冲。
3. `presentation_us < target_us` 时保持静音，等画面到达目标后按越过量计算 `skip_us`。
4. `scheduleStart()` 只应用本 epoch 的 `skip_us` 和绝对墙钟启动点；旧 epoch 调用无效。
5. 正常路径不允许 `offset_us`。

起播后观察 1s/5s/10s：

```text
drift_us = presentation_us - audio_content_us
```

它是趋势指标，不是真实音画偏差。

### 7.2 RUNNING 闭环

- `E_sync = median(presentation_us - audio_content_us)`，取连续 `N` 个 500ms 样本。
- 有效样本要求 `vpu_state=STABLE`、非 transition、队列稳定、帧持续提交、音频已启动且队列稳定。
- `PRESSURE` 只记录不纠偏；`STALL` 进入 `SUSPENDED_VPU` 并交 D22/watchdog。
- `|E_sync| <= D_dead`：CONVERGED。
- `D_dead < |E_sync| <= D_micro` 且方向连续：CORRECTING，在 AudioPipeline 做有上限的 PCM 重采样补偿。
- `|E_sync| > D_reanchor` 或纠偏不收敛：请求 compat 创建 `drift_reanchor` epoch。
- 一次只允许一种执行器：PCM 重采样或重新 anchor，不能同时生效。
- 阈值和采样数先通过 env 配置，由真机矩阵标定；未标定时关闭自动纠偏。
- 稳定后保留滞回窗口；连续失败由 SlPlayer 上报 `SL_EVT_SYNC status=failed`，compat 写 `SYNC_END status=error`。

## 8. IPC、日志与检查契约

统一日志前缀沿用 D27：`[HH:MM:SS.mmm][SOURCE][run][session][gen][req]`。

事件格式：

```text
SYNC_BEGIN      epoch=<n> reason=<r> target_us=<n> source=<s> qn=<n> wall=<ms>
SYNC_PREPARED   epoch=<n> first_pts_us=<n> queue_us=<n> audio_seek_us=<n> audio_quiet=<0|1> quiet_ack=<s> quiet_seq=<n> sink_queue_samples=<n>
SYNC_START      epoch=<n> skip_us=<n> present_us=<n> audio_queue_us=<n> audio_media_us=<n> audio_mode=<audible|silent> wall=<ms>
SYNC_DRIFT      epoch=<n> elapsed_s=<n> present_us=<n> audio_content_us=<n> drift_us=<n> qn=<n> frame_age=<ms> vq=<ms> bp=<0|1> vpu_state=<s> submitted_us=<n> queued_audio_media_us=<n> compensation_ppm=<n>
SYNC_END        epoch=<n> status=ok|error|superseded reason=<r>
```

检查规则：

- 每个 d28 epoch 恰好一个 `SYNC_BEGIN` 和一个 `SYNC_END`；reanchor 生成新 epoch，不复用旧终态。
- `SYNC_START` 晚于 `SYNC_PREPARED`，同一 epoch 只能一次。
- `audio_quiet=1` 必须带 `quiet_ack`；`finishSeek` 时 `quiet_seq` 必须有对应 seek done，且 `sink_queue_samples` 证明旧 PCM 已清空。
- 同一 epoch 的 `target_us` 在 CMD/meta/PLAYER/AUDIO 中一致。
- 旧 `start=<秒>` 必须能由 `target_us` 转换得到；超过兼容精度容差时检查 FAIL。
- 自动纠偏启用时，`SYNC_DRIFT` 必须记录 `queued_audio_media_us` 和 `compensation_ppm`。
- 正式 D28 验收 `sync_offset_ms=0`。
- 只有 `sync_mode=d28` 强制完整 `SYNC_*` 契约；其他模式按 D27 契约检查“不回归”。

## 9. 原子实施步骤

每步必须单独提交、单独验证；前一步未验收不得进入下一步。第 10、11 节的测试是以下步骤的完成门禁，不在其他章节重复分派任务。

| 步骤 | 内容 | 完成标准 |
|---|---|---|
| D28-S01 契约定稿 | 以第 2、5、7 节为唯一依据，冻结误差、门禁、状态、执行器和变更控制 | 本文评审通过；不改代码 |
| D28-S02 协议与日志基础 | 时间字段迁移到整数微秒；meta 承载 `epoch/target_us/sync_reason`；新增 `SL_EVT_SYNC`；compat 建立 epoch 注册表与终态写入；heartbeat 增加可选 `vpu_state`；日志补齐检查字段 | `check-debug-run.sh` 按 `sync_mode` 检查；compat 写终态；`mixed_compat`/`mixed_daemon` 各跑一次确认旧路径不回归；同步行为不变 |
| D28-S03 VPU 状态 | SlPlayer 实现 `STABLE/PRESSURE/STALL` 并随 heartbeat 上报；D22/D28 只读 | D22 与 D28 使用同一状态；旧 daemon 缺字段时按 `mixed_compat` 验收，不启用 D28 闭环 |
| D28-S04 基线矩阵 | 关闭自动纠偏，按第 10 节跑跨场景、跨清晰度矩阵，记录 1s/5s/10s drift | 得到各档位漂移分布和异常样本，证据写入 02 |
| D28-S05 阈值表 | 根据基线确定 `D_dead`、`D_micro`、`D_reanchor`、采样数和最大补偿速率 | 阈值写回本文，不靠单次听感 |
| D28-S06 控制器骨架 | SlPlayer 实现 `CONVERGING/CONVERGED/CORRECTING/SUSPENDED_VPU`；失败上报 compat；恢复路径完整；默认关闭纠偏 | 所有状态变化有日志；终态只有 compat 写；开启不纠偏时音频行为不变 |
| D28-S07 场景入口 | restart 收敛到 compat 的 `beginEpoch()`；取消隐式续播 seek；pause 用 `requestSeek(target_us)` 和 ack 达成 quiet；resume 不二次 seek；所有目标归一化 | 每个 restart 只有一个 epoch；pause 日志可追溯 ack；第 11 节兼容矩阵全部通过 |
| D28-S08 PCM 补偿器 | 实现有上限重采样补偿；记录 `audio_media_us/queued_audio_media_us/compensation_ppm`；不允许全局 offset | env 开启后可量化；未开启与基线一致；媒体时间可审计 |
| D28-S09 重新 anchor | 大误差或不收敛时创建新 epoch；限频；复用 replay 取消逻辑 | 无竞态 open/seek；每次 reanchor 有原因 |
| D28-S10 D22 联动 | PRESSURE 禁止纠偏；STALL/hard 交 D22/watchdog；新流重新计算 | hard run 无旧 epoch 纠偏竞争 |
| D28-S11 启用与全矩阵 | 按阈值启用控制器，完成第 10、11 节全矩阵 | 结构检查 PASS；兼容矩阵 PASS；用户真机确认同步 |

D28-S06/D28-S08/D28-S09 可并行设计，但必须分别验收，最后在 D28-S11 合并启用。

## 10. 真机测试矩阵与验收

统一使用 `tools/steamlink-app/debug.sh --diag --sync-debug`，禁止旧脚本。至少三类 VPU 档位：稳定 720P、稳定 1080P、1080P/1080P60 高反压或失败片源；每类至少两轮，单轮不少于 60 秒，从干净 VPU 基线开始。

| 场景 | 当前支持 | 要求 |
|---|---|---|
| 冷播无历史 | `play` 已有 | D28 后完整 epoch 时间线 |
| 历史续播 | 需新增或手工 + 日志 | `target_us` 唯一权威 |
| seek_forward/backward | 已有；D28-S07 后使用 `target_us/delta_us` | 旧秒参数归一化，冲突报 CMD error |
| pause_resume | 已有 | pause ack、resume 无二次 seek |
| quality_change | 已有 | 双向切换，`target_us` 不截断 |
| hard/no_frame 自动降级 | 现有质量场景可诱发 | 新 qn 流真实起播且不继承旧纠偏 |
| watchdog replay | 需新增或自然触发 + 日志 | 新 epoch，旧终态由 compat 写 |
| CDN failover | 需新增或手工 + 日志 | 使用错误时精确位置 |
| EOF 自动续播 | 需新增或自然触发 + 日志 | 新内容、新 session、新 epoch |
| 直播连接与重连 | `live:* + play` 可测连接 | 重连需新增控制场景 |

验收标准：

- `target_us` 是整数微秒；自动降级不得出现整秒截断。
- d28 run 每个 restart 只有一个 epoch，无竞态 open/seek。
- d28 run 使用统一的 `SYNC_BEGIN → SYNC_PREPARED → SYNC_START` 时间线。
- `CORRECTING/reanchor/SUSPENDED_VPU` 有原因和前后误差。
- PRESSURE/STALL run 不出现 PCM 补偿。
- 阈值来自基线分布，不来自单次听感。
- 正式验收 `sync_offset_ms=0`。
- 用户确认画面与声音同步；日志不能替代真机结论。

## 11. 兼容性实施与测试矩阵

D28 是渐进重构。新字段采用追加方式；旧 daemon 忽略未知 meta 字段；新 daemon 在没有 `epoch/target_us/vpu_state` 时退回旧 D27 行为。manifest 记录 compat/daemon MD5 和 `sync_mode`，检查脚本按模式选择契约。

| 场景 | compat | daemon | 实施要求 | 验收 |
|---|---|---|---|---|
| 全量 D28 | 新 | 新 | meta、open/seek `*_us`、heartbeat `vpu_state`、compat 注册表和终态全部生效 | `sync_mode=d28`；完整 `SYNC_*`；用户确认同步 |
| 新 compat + 旧 daemon | 新 | 旧 | compat 仍生成至少毫秒精度的旧 `open.start`；旧 daemon 按旧字段播放 | `sync_mode=mixed_compat`；不检查 `SYNC_*`；play/seek/pause/quality 与旧基线一致 |
| 旧 compat + 新 daemon | 旧 | 新 | 新 daemon 无 epoch/meta 时不创建 epoch、不启用 D28；只用旧字段 | `sync_mode=mixed_daemon`；D27 契约通过；无 D28 误触发 |
| 旧秒级输入 | 新 | 新 | 整数秒与小数秒在 compat 边界转成 `target_us` | 两种输入各跑一次；CMD 同时记录旧值和 `target_us` |
| 新旧目标并存 | 新 | 新 | `target_us` 为唯一权威；旧值必须可转换 | 超过精度容差检查 FAIL |
| `vpu_state` 缺失 | 新 | 旧 | D22 用旧 `bp/vq/pos`；D28 闭环不启用 | `mixed_compat` 下 hard/backpressure 按 D22 旧契约 PASS |
| pause 新路径 | 新 | 新 | `requestSeek(target_us)` + `finishSeek` ack + `quiet_seq` | 无二次 seek，PCM 清空证据完整 |
| pause 旧路径 | 新 | 旧 | 保持 `setPaused(true)` + resume seek 旧行为 | `mixed_compat` 下暂停恢复无回归 |

每个原子步骤至少跑一次 `mixed_compat` 或 `mixed_daemon`，确认新增字段不影响旧路径；D28-S07 必须跑完本节全部兼容场景。
