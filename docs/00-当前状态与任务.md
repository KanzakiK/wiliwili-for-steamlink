> 这是本项目**唯一的任务看板**；只维护当前阶段、下一步、任务状态和必要约束。

更新：2026-11-18。

## 项目目标

在 Steam Link（ARMv7 单核、约 263MB 可用内存、GLES2）上运行原生 B 站客户端：

- 移植 wiliwili 的 UI / API，不手写 UI、不改 wiliwili 布局/样式。
- 播放内核使用 SLVideo 硬解 + FFmpeg 解封装 + SLAudio，不引入 mpv 本体。
- UI 通过 libmpv 兼容层 + IPC 控制独立 `slplayer_daemon`。

当前已落地的关键边界：

- 播放器语义统一由三层契约处理：wiliwili UI 表达目标，兼容层翻译 mpv 语义，daemon/SlPlayer 上报已完成的当前状态。
- IPC 命令/事件带文件 generation 与 request id；兼容层过滤过期代次事件。
- Range 重定位处理远距离 seek；续播起播/暂停恢复不再重复重建 SLVideo stream；连续重建至少间隔 400ms。
- SPS 改写默认关闭；`SL_SPS_REWRITE=1` 仅作实验，因为用户多轮视觉确认 `refs 7→4` 会让不少视频花屏。
- D14 的 UI/GPU 51.84MB SHM 申请失败仍是独立未修问题。

历史细节见 [02 日志](02-开发进度日志.md)，设计依据见 [05 播放器设计](05-播放器替换设计.md) 与 [06 VPU 架构](06-VPU鲁棒性架构.md)。

## 下一步优先级

1. **D14 高清源与 UI/GPU OOM**：51.84MB 纹理已定位并降采样；固定 1000 kbit/s、按 `bw×8` 设置码率、完全不设置 setter 三条路线均已否定，现保持与 Kodi 一致。剩余片源级队列停滞转 D22；历史 SHM 现场继续作为证据保留。
2. **D21 1080P 偶发黑屏**：空队列 VPU 重建、首帧前 watchdog 误杀和 CDN 断流判死已修；720P 稳定，1080P 的问题片源仍会在高参考帧码流上进入队列停滞，转 D22 跟进。
3. **D22 播放健康检测与自动降级**：不再按片源编码信息预判 1080P 能力；720P 目前无不能播案例，失败时直接降到 720P，降到 1080P 无意义。健康判据用喂帧与呈现位置推进，阈值先用可调实验参数，找几个失败片源实测校准；复用现有 500ms 心跳/250ms 进度事件，不增加高频轮询。网络错误按“近期条件排除”，不能永久豁免；降级通过 `VideoView::HINT` 提示用户。日志只记录状态转换，正式包不保留每秒诊断。
4. **P0 最终验收（按需）**：只有用户仍遇到 seek/暂停/续播问题，或准备正式验收时，才补 D12 分段耗时与完整真机清单。
5. **旧报告待复现**：D3、D8、D9、D12 只在再次观察到具体现象时处理；不因为历史编号仍开着就主动改代码。
6. **非当前缺陷的设计项**：D6、3.5b、3.5d、3.6 作为能力边界/设计储备，没有明确症状和用户需求时不启动。D16、D17 已完成，不再列入优先级。

## 设备与基线

- 设备：`root@<device-ip>`，密码 `<device-password>`。
- 部署唯一入口：`sh tools/steamlink-app/install.sh`；禁止把二进制/资源/测试视频长期放进 `/tmp`（tmpfs 直接吃内存）。
- 日志：`/tmp/wiliwili.log`；测试与自动复现日志在 `/home/apps/bilibili/3.5c-test/` 与 `/home/apps/bilibili/p0-*.log`。
- 当前配置：自动全屏、硬件解码选项（桩层无实际作用）、`image_request_threads=1`、`player_inmemory_cache=0`、`texture_cache_num=100`、`video_quality=64`。
- 设备重启后时间可能短暂回到 1970，导致 CDN 证书校验失败；测试前用主机时间戳校准。
- 怀疑 VPU 脏状态时先 `reboot -f`，再用已知正常流确认基线；脏 VPU 下的对比结论无效。

## 常用命令

```sh
# 构建
cmake --build ~/build-slplayer
sh tools/build-wiliwili.sh

# 部署
sh tools/steamlink-app/install.sh

# 真机回归
sshpass -p <device-password> ssh root@<device-ip> \
  "sh /home/apps/bilibili/3.5c-test/test-3.5c.sh all"

# 日志
sshpass -p <device-password> ssh root@<device-ip> "tail -40 /tmp/wiliwili.log"
```

正式启动脚本支持参数透传；测试 patch 提供 `--open-bv`、`SL_TEST_PAUSE_AFTER_SEC`、`SL_TEST_SEEK_SEQUENCE`、`SL_MEDIA_TAG`、`SL_DANMAKU_DEBUG`，均不进入正式业务逻辑。
