更新：2026-11-20。

## 项目目标

在 Steam Link（ARMv7 单核、约 263MB 可用内存、GLES2）上运行原生 B 站客户端：

- 移植 wiliwili 的 UI / API，不手写 UI、不改 wiliwili 布局/样式。
- 播放内核使用 SLVideo 硬解 + FFmpeg 解封装 + SLAudio，不引入 mpv 本体。
- UI 通过 libmpv 兼容层 + IPC 控制独立 `slplayer_daemon`。

## 当前阶段

**P0 语义对齐与真机验收已完成，wiliwili 主体功能基本闭环。** 3.5a/3.4b/3.4c/3.5c、D1/D2/D5/D7/D10/D11/D13/D15/D17～D20 均已真机闭环。D6 按原生行为/能力边界关闭；D8/D9/D12 在当前架构下无新证据，关闭但保留重开条件。近期又完成了下载中断续传、VPU 重建/fatal 收敛、启动参数诊断入口；用户确认反复切分辨率已不再遇到播放失败后的 OOM 崩溃，720P 稳定，多个 1080P 片源也能正常播放。

当前未解决项不再归为 P0 验收缺口，而是两类后续工作：一是**片源解码能力边界**，部分高参考帧 1080P/1080P60 会进入 VPU 队列停滞；二是**播放架构/策略优化**，例如同步和播放卡顿提示。D14 的 51.84MB 纹理问题已定位并降采样；1000 kbit/s、按 `bw×8` 设置、完全不设置目标码率三条路线均已否定，现保持不调用 setter。D24、D27 已完成：源码单一来源、0 patch 构建、统一 debug 日志与场景入口已落地。D23 的音频 seek 非阻塞、墙钟兜底移除、同步失败判据、亚毫秒对齐参数和 50ms 音频块已落地，但不同清晰度仍有不一致的轻微音频领先，调参暂停且任务未关闭。D28 已完成减法设计，按四状态、双 ready bit 和单一 active epoch 实施，长期纠偏能力延期；D23 的后续工作并入 D28，不再继续手调固定偏移。D22 的软/硬提示链以及 1080P 三档 hard/no_frame 自动降到 qn=64 已真机验证，但真实软卡顿阈值尚未校准。后续按 **D28 实施 → D22 校准 → D26 → D25** 顺序处理。

当前已落地的关键边界：

- 播放器语义统一由三层契约处理：wiliwili UI 表达目标，兼容层翻译 mpv 语义，daemon/SlPlayer 上报已完成的当前状态。
- IPC 命令/事件带文件 generation 与 request id；兼容层过滤过期代次事件。
- Range 重定位处理远距离 seek；续播起播/暂停恢复不再重复重建 SLVideo stream；连续重建至少间隔 400ms。
- SPS 改写默认关闭；`SL_SPS_REWRITE=1` 仅作实验，因为用户多轮视觉确认 `refs 7→4` 会让不少视频花屏。
- `视频已上屏` 日志只表示 VPU 队列稳定、可安排音频启动，**不是画面呈现证据**；视觉结论依赖用户确认或截图。
- 诊断能力常驻源码，通过启动参数按次开启，正式启动默认关闭。

历史细节见 [02 日志](02-开发进度日志.md)，设计依据见 [05 播放器设计](05-播放器替换设计.md) 与 [06 VPU 架构](06-VPU鲁棒性架构.md)。

## 设备与基线

- 设备：`root@<device-ip>`，密码 `<device-password>`。
- 部署唯一入口：`sh tools/steamlink-app/install.sh`；禁止把二进制/资源/测试视频长期放进 `/tmp`（tmpfs 直接吃内存）。
- 日志：`/tmp/wiliwili.log`；测试与自动复现日志在 `/home/apps/bilibili/3.5c-test/` 与 `/home/apps/bilibili/p0-*.log`。
- 当前配置：自动全屏、硬件解码选项（桩层无实际作用）、`image_request_threads=1`、`player_inmemory_cache=0`、`texture_cache_num=100`、`video_quality=64`。
- 设备重启后时间可能短暂回到 1970，导致 CDN 证书校验失败；测试前用主机时间戳校准。
- 怀疑 VPU 脏状态时先 `reboot -f`，再用已知正常流确认基线；脏 VPU 下的对比结论无效。

## 常用命令

```sh
# 构建
cmake --build ~/build-slplayer
sh tools/build-wiliwili.sh

# 部署
sh tools/steamlink-app/install.sh

# 真机回归
# 旧 test-3.5c.sh / compat_test 已封存，禁止运行；同步验收用真实播放页 + --diag --sync-debug
```

正式启动脚本支持参数透传；debug 场景由 `tools/steamlink-app/debug.sh` 设置 `SL_DEBUG_RUN_ID/CONTENT/SCENE/ARGS` 触发，源码内对应逻辑在无这些变量时完全不生效。`SL_DANMAKU_DEBUG` 仍是独立诊断开关。
